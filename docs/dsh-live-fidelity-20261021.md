# 长对话真实模型对照：发现默认 trim 的事实损失

日期：2026-10-21。产品基线：`65bfe5d`，分支 `codex/dsh-compatibility`。

## 结论

本次样本中，默认压缩减少了输入 token，但删除了旧消息中间的关键事实。
不能以此前的协议测试通过或单句事实保留率，宣称 DSH 长期陪伴聊天无损适配。

| 条件 | 实际输入 tokens | 实际输出 tokens | 正确回答 | 缓存命中 tokens |
| --- | ---: | ---: | ---: | ---: |
| 不压缩 | 2785 | 43 | 5/5 | 0 |
| 默认 trim，保留最近 6 轮 | 2082 | 43 | 4/5 | 0 |

输入减少 703 tokens，约 25.24%。这是单个合成样本的用量对照，不是普遍节费比例。
未查询余额或账单，没有记录货币费用；缓存和真实对话分布也会影响费用。

## 实验方式

通过本机现有环境变量中的 DeepSeek API key 调用官方接口；未显示、保存或修改
密钥。先只读查询模型列表，确认可用 `deepseek-flash` 与 `deepseek-v4-pro`。
正式对照使用 `deepseek-flash`，关闭思考，JSON 输出，最大输出 256 tokens。
两次请求均 HTTP 200、`finish_reason=stop`；没有失败重试。

请求经过真实 roleplay-slim FastAPI 入口和真实 HTTP 上游客户端。测试使用
TestClient，而非网络监听；这一步没有经过 DSH runtime、IM 插件或 DSH 原生
compaction。因此它证明压缩与模型回忆之间的影响，不是 QQ/微信端到端验收。
此前独立的 DSH 适配器协议探针见 `dsh-compatibility-cn.md`。

记录完全合成：system 一条前缀事实；第一条旧用户消息首句、中间句和末句各
一条事实；接着 35 轮普通周末安排对话；最后近期消息一条事实，并询问五条暗号。
所有助手历史只是普通回应，没有重复暗号。提示要求缺少事实时返回 UNKNOWN。
两组输入相同，区别只在压缩配置：

- 不压缩：禁用 history_window、whitespace_normalize、dedupe_verbatim_tail。
- 默认：`CompressorConfig()`，默认 trim、保留最近 6 轮。
- 统计使用 API 返回的 usage，不用本地 token 估计值代替。

## 实际回答

| 事实位置 | 标准值 | 不压缩 | 默认 trim |
| --- | --- | --- | --- |
| system 前缀 | PFX482 | PFX482 | PFX482 |
| 旧消息首句 | FST731 | FST731 | FST731 |
| 旧消息中间句 | MID926 | MID926 | UNKNOWN |
| 旧消息末句 | LST815 | LST815 | LST815 |
| 最近消息 | REC364 | REC364 | REC364 |

压缩结果的结构检查也确认：`MID926` 不再出现在送给模型的正文中，其余四项仍在。
因此该失败不是单纯模型偶然回忆失误；默认首尾句截取删除了来源事实。

另运行既有离线单句事实基准：3 个种子、每组 50 轮、保留 6 轮，33/33 条
事实仍在，平均估算 token 减少 14.2%。该语料刻意把事实写成单句，因此不能
代表多句消息中间的信息也能保留。离线子串存活亦不等于模型回忆正确率。

## 下一步门槛

先增加多句中间事实、否定、纠正、人物关系和跨渠道来源的保真用例，再评估
保守配置或更合适的压缩策略。不能只检测暗号、数字等显式模式便宣称解决语义
事实损失。保守配置若关闭历史截取，应同时如实报告可能降低压缩收益。

在此之前，不将默认配置作为 DSH 陪伴聊天的无损方案推广；不改用户正在运行的
DSH，不修改其历史记录，也不调整原有权限或工具审批。

## 同日修复后的真实模型复测

源码默认改为 `preserve` 后，以完全相同的合成输入再次调用 `deepseek-flash`：

- HTTP 200，`finish_reason=stop`，五条暗号全部正确（5/5），`MID926` 恢复。
- 送出的消息数组与原输入一致，输入 2785 tokens、输出 43 tokens。
- API 返回缓存命中 2560、未命中 225 tokens。这次缓存受到之前请求的预热影响，
  不能把缓存费用差异算作本次修复的压缩收益。
- 该样本没有可去重的 footer 或冗余空白，因此新默认没有减少输入 token。

此次修复消除了默认首尾句截取导致的事实删除，并未实现“任意事实都能无损压缩”。
默认仍能整理空白和重复提示；用户主动开启 trim、drop、摘要、动作删除或 token
预算时仍可能丢失信息。Anthropic 旧工具结果默认完整保留，裁剪需明确设置
`anthropic_trim_tool_results=true`。摘要失败、空白或非法结果保留原历史，回调使用
深拷贝输入，避免回调修改后失败污染原文。

仅修改源码和新生成的通用启动器配置；不改变旧配置、桌宠专用安装器或现有发布包。
